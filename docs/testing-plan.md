# Testing plan — cross-boundary behavior

**Status:** follow-up design, not a live tier or a validation report. The current
inventory, required checks, triggers and evidence limits are authoritative in
[testing.md](testing.md). Update that inventory in the same PR whenever a tier
or pack changes.

## Current boundary

The routing trajectory pack has five cases and five repeats. It tests selected
acceptance prerequisites, scope widening, irreversible-action consent, direct
bounded work and continuity of pending decisions. Core supplies shared rules;
verify-work supplies an optional acceptance method. These cases do not establish
native-session behavior or model effectiveness until actually evaluated.

Typed routing tests check specialist/service/guard composition. Agentic fixtures
exercise deterministic adapter, pairing, artifact and lifecycle properties;
fixture success does not prove real dispatch, independent review or host parity.
Legacy `redgate-*` card IDs and `.redgate/` storage remain compatibility data,
not an active product, default round protocol or promise of universal coverage.

## Next evidence to collect

1. Test missed routes, false positives and mixed-task transitions against the
   current ownership contract. Keep simple requests free of unnecessary services.
2. Test claims against accessible current evidence and preserve reported,
   inferred and independently verified distinctions through handoff.
3. Use actual supported native hosts to test interruption, stop propagation,
   contract drift and permission boundaries. Report unavailable capabilities
   rather than treating a fixture as host qualification.
4. Evaluate whether users orient faster with less effort using the separate
   synthetic re-entry pilot. Preserve accuracy and permission boundaries; do not
   reuse or alter PR129's frozen corpus or criteria.

Use matched controls, repeated valid samples and explicit fault-versus-verdict
classification. Demonstrate relevant mutations fail before claiming a gate
measures its subject. Native/model execution requires the applicable cost,
permissions and disclosure authorization; this plan starts no runs.

## Historical design

The earlier issue89 plan proposed Redgate rounds, universal envelope probes and
new product-specific pier tasks. Those assumptions are superseded by the shared
ownership architecture. Its source and recorded research lessons remain available
in the [pinned pre-refactor plan](https://github.com/JRichlen/agent-plugins/blob/2ff596caf3be9fd59ebfe42d17b05ccab1f1da1d/docs/testing-plan.md).
Historical run notes concern their original inputs; they do not validate the
current service extraction. Retain useful testing techniques without reviving
retired governance or creating parallel verdict logic.
