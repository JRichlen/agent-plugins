# Follow a real piece of work

The bug and feature walkthroughs use completed repository changes and available
evidence. The handoff guide is an explicitly labeled template for a review
boundary, not a claim that an independent review has completed. They are
scoped demonstrations, not fabricated before/after transcripts or controlled
proof that a skill improves outcomes.

| Your task | Walkthrough | Useful next depth |
|---|---|---|
| Diagnose a failure | [Repair gallery capture launch](bug-fix.md) | Failure source and regression controls |
| Add a small feature | [Build a source candidate](small-feature.md) | Design seam, reproducibility and publication boundary |
| Move work to another session | [Hand off the stack](handoff.md) | Live source pointers, unresolved state and authority |

New here? [Complete the first task](../getting-started.md) before learning the
architecture. Looking for measured effectiveness? Read the
[evidence limits](../testing.md#not-yet-covered-by-current-evidence), not a walkthrough as a benchmark.
