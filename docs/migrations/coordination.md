# One owner for delegated execution

The Jori product and plugin identity are retired. Its old directory is only a
notice. The merged delegated-intelligence service owns briefs, dispatch, output
ownership, integration and recovery. It is selected for a bounded unit and exits
when every assignment is accounted for.

## Removed redundancy

| Removed source or responsibility | Canonical owner now |
|---|---|
| Jori's generic coordinator persona and substantive-delegation mandate | Core selects a method; delegated-intelligence executes only the selected unit |
| Jori board plus delegated-intelligence board | Existing task/project record with the core state contract; Wayfinder owns persistent plans |
| Jori model baselines and DI's branded tier ladder | Configured model/effort choices recorded in a bounded brief |
| Two independent retry policies and DI's repeated two-retry rule | stop-rule owns accounting, bounds and stop reports |
| Duplicated question, authority, publishing and status rules | core/OPERATING.md |
| Automatic observer, premium review and follow-up scheduler | Removed; learning proposals use recurrence-detector and existing decision records |
| Generic verification instructions in the coordinator | verify-before-claim owns completion evidence; an independent check must actually be independent |

Whole-cycle cost accounting and a proportional existing record survive as short
execution guidance. No dashboard, provider ranking, persona or automatic policy
adoption is retained merely because it existed.

## Compatibility

The old plugin is no longer offered for new installation. The replacement is:

```text
/plugin install delegated-intelligence@jrichlen
```

Choose its installed command through the host's command menu. The old plugin
namespace is not silently redirected; a thin notice cannot implement an old
installed command. Existing pinned source remains available at
[2ff596c](https://github.com/JRichlen/agent-plugins/tree/2ff596caf3be9fd59ebfe42d17b05ccab1f1da1d/plugins/jori).

An existing global Jori activation fragment requires an explicit reviewed
replacement with the approved core/host adapter. This repository change neither
edits that file nor assumes it has been removed. Standalone service installation
carries a generated core-contract copy, but does not activate always-on host
instructions. Host adoption must verify that separate layer before claiming
the system is active.

## Restore and verification boundary

Before removal, all 18 tracked Jori source blobs were restored from
`2ff596caf3be9fd59ebfe42d17b05ccab1f1da1d` into an isolated scratch directory.
Every restored Git blob SHA matched. This proves source-content restoration;
it is not a claim of installed host behavior or symbolic-link parity on Windows.

Full rollback restores the retired package plus its catalog, routing, coverage
and caller changes together from the migration base. Restoring only the source
directory without its catalog entry is incomplete. No live-system restoration
is needed here because no installed system was changed.

Free source-contract checks and mutation controls cover the surviving method.
They do not establish model effectiveness, total-cost improvement or runtime
parity. The repository's full required gate and real-host adoption checks remain
separate requirements.
